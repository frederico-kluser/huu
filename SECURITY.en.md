# Security Policy

> **Versão em português:** [SECURITY.md](SECURITY.md)

`huu` runs LLM agents with access to your repository and your provider
credentials — security is part of the product, not an appendix. Thank
you for helping keep it safe.

## Supported versions

| Version | Support |
|---|---|
| Latest release (`huu-pipe` on npm / `ghcr.io/frederico-kluser/huu` on GHCR) | ✅ Security fixes |
| Older versions | ❌ Please upgrade to the latest |

Recommendation: pin an image tag (`HUU_IMAGE`) for reproducible builds,
but follow security fixes on the current release line.

## How to report a vulnerability

**Never open a public issue for a vulnerability.** Pick one of the
private channels:

1. **GitHub Security Advisories** (preferred): *Security* tab →
   *Report a vulnerability* — the report is private and goes straight
   to the maintainer.
2. **E-mail:** [kluserhuu@gmail.com](mailto:kluserhuu@gmail.com) with
   the subject `[SECURITY] <short summary>`.

Include in the report:

- Description of the impact and the attack vector (how an attacker
  would get there).
- Reproduction steps or a PoC **without real data**: never paste API
  keys, tokens, third-party secrets or customer data — describe them
  (`an OpenRouter key in the sk-or-… format`) instead of reproducing
  them.
- Affected version (`npm view huu-pipe version` / image tag) and
  environment (OS, Docker or native).

## What happens after you report

- **Acknowledgement** within 7 days, with an initial assessment.
- **Dialogue** about the impact and the fix; you get credit in
  `CHANGELOG.md` if you want (or an anonymous report).
- **Coordinated disclosure**: the default embargo is up to 90 days, or
  sooner if the fix ships before that. After the fix, we publish the
  details.

## Scope

- The runner (`src/`, `scripts/`, `Dockerfile`, the GHCR image) and the
  npm package `huu-pipe`.
- **Credential handling**: the key registry
  (`src/lib/api-key-registry.ts`), Docker secret mounts, secret
  scrubbing in logs/transcripts, and the subprocess environment
  isolation.
- This repository's CI workflows.

## Out of scope

Out of scope (please do not file security reports for these):

- **Model outputs**: content generated by LLMs (code, text,
  hallucinations) — the model's and the human reviewer's
  responsibility.
- **Third-party pipeline content**: pipelines you wrote or installed are
  yours; review them before running.
- **External providers**: vulnerabilities in DeepSeek, OpenRouter or
  GitHub belong to their respective owners.
- **User misconfiguration**: keys committed to your own repository,
  `--no-docker` in a sensitive environment, your runner's permissions.

## Credentials when using huu

- Keys enter through environment variables (`DEEPSEEK_API_KEY`,
  `OPENROUTER_API_KEY`, or the `_FILE` suffix pointing at a file) and
  mount into the container as secret mounts — they never go into argv
  commands or into an agent's prompt.
- Each run spends **exactly one** key — the active provider's; the other
  providers' keys are stripped from the subprocess environment.
- If your key leaked: **rotate it first** at the provider
  (openrouter.ai/settings/keys · the DeepSeek console) and then tell us
  if the leak came from huu.

A final note: `huu` sends prompts to models and writes to your repo by
design. Treat the pipelines you run with the same care as any
third-party code.
