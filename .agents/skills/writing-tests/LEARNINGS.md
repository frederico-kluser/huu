- [2026-06-12][source:inference][task:dag-waves][probation] Captures inside parallel-pool stub factories arrive in COMPLETION order, not creation order — assert by identity (sort captured tasks by file, find() prompts by content), never by arrival index. A capture-order assertion is a latent flake that surfaces only under load.
- [2026-08-04][source:inference][task:devgraph-test-hardening][probation] A test that only inspects an artifact's BYTES passes against filler text of the right size. `vendor/reactflow.test.js` used to assert on the bundle's source string (an `export{}` clause, a banner) — satisfiable by ~150 KB of junk with the right substrings. The rewrite `await import()`s the bundle off its `file://` URL and asserts BEHAVIOUR (all 30 exports resolve, `React` hooks share IDENTITY with the re-exported names — two React copies would export the same names with different functions). If an artifact matters, the test must EXECUTE it; and the proof that the new test is real is applying the mutant (swap the file for filler) and showing the failure.
- [2026-08-04][source:inference][task:devgraph-test-hardening][probation] An invariant asserted only in a file-header comment is deleted by the next refactor in silence. `graph-store.ts`'s tmp+rename atomicity had a whole paragraph of prose and NO test — the suite stayed green against removing the mechanism entirely. The test that closes it observes the OBSERVABLE CONSEQUENCE rather than the implementation (rename SWAPS IN a new inode: the target's inode is never the one being written into, and a reader holding an old descriptor still sees the old version), plus the staging file lands INSIDE the target directory because rename is only atomic within one filesystem. Rule: a header paragraph claiming a property is a TODO for a named test block, not coverage.
- [2026-08-04][source:inference][task:devgraph-test-hardening][probation] Guard every "for each item, assert X" loop with an explicit non-vacuity check — `expect(list.length).toBeGreaterThan(0)` (or a known count) BEFORE the loop. An empty list satisfies "all items obey" trivially, so a filter that quietly eats its input turns the strongest-looking assertion in the file into a no-op. Live precedents: `graph-to-pipeline.test.ts` "names every dependsOn entry EARLIER in the array — and NOT vacuously", the memory-step twin at the same file, and `graph-validate.test.ts`'s guard against an empty issue list.
