- [2026-08-01][source:inference][task:i18n][probation] `src/lib/i18n/` is the lowest layer in the tree and is imported by EVERY other one (cli.tsx, app.tsx, ui/components, web/server, web/serve, lib/git-preflight), so it must import nothing but itself — `types.ts` (locale list, `normalizeLocale`) is dependency-free precisely so `cli.tsx` can call `initI18n()` at the top of the module, BEFORE the docker gate and before React/Ink are pulled in. That placement is what makes the wrapper path's stderr messages translated too. Two conventions the conversion forced: (1) a module-level `const HINTS = [{label: t('…')}]` translates at IMPORT time, before `initI18n()` resolves the locale, and also breaks the "module bodies stay pure" rule — PipelineEditor's `EDITOR_NAV_HINTS`/`EDITOR_ACTION_HINTS` had to become `editorNavHints()`/`editorActionHints()` functions; (2) `t` is a one-letter name that COLLIDES with the repo's habit of naming a delegated event target or a map callback `t` — the client typecheck caught four (`board.js` drawer retry, `settings.js` pool/status handlers, `PipelineAssistant`'s history map). Rename the local, never alias the import, so every call site reads the same.
- [2026-08-01][source:inference][task:i18n][probation] Translating the Ink UI is mostly mechanical EXCEPT where layout depends on the English string's width. Two real cases: `RunModal`'s git block used hand-padded labels (`'  branch   '`, `'  worktree '`) whose alignment dies in any other language — the padding had to move OUT of the string into `key.padEnd(9)` at the render site; and `<Text bold>{label}</Text>` inline inside a sentence (ApiKeyPrompt's "Paste your **OpenRouter** API key") cannot survive translation because word order is the translator's to choose — collapse it to ONE key with a `{label}` placeholder and accept losing the inline bold. Also: `card-state.ts` must stay locale-blind. It is a pure classifier mirrored in the browser and pinned by two test files, so the codes it returns (`NO CHANGES`, `READY`) stay English and `tStatus(code)` translates them at the render boundary in `RunKanban` — translating inside the classifier would break both mirrors and both tests at once.
- [2026-08-01][source:inference][task:i18n][probation] The browser gets its strings from the SERVER (`GET /api/i18n` → `{locale, defaultLocale, locales, messages}`), never from a duplicated table — one catalog in `src/lib/i18n/` feeds both front-ends, which is the same reasoning as devModelRoles/devMethodologyOptions riding `/api/bootstrap`. Two contract details that matter: the route is deliberately OUTSIDE the token gate (the client must paint its own chrome before it has a token, and catalogs carry no secrets), and `boot()` awaits `initI18n(api)` BEFORE anything renders so every later `t()` is synchronous. Static markup declares its strings as `data-i18n` / `-html` / `-placeholder` / `-title` / `-aria-label` attributes and `applyI18n()` walks them; because it is idempotent, the ⚙ language switcher just refetches + re-applies + re-renders instead of reloading — a reload would drop the SSE stream and the whole board. `client/i18n.js` keeps the no-top-level-DOM rule (`applyI18n` takes anything with `querySelectorAll`), so its 14 tests run in Node with a hand-rolled fake DOM.
- [2026-08-01][source:inference][task:i18n][probation] A source-SCANNING test is the only thing that catches a translation key nobody ever renders in a test run (`src/lib/i18n/coverage.test.ts`: walk `src/`, collect every key the app references, fail on an untranslated reference or an orphan catalog key). Two traps found while writing it: (1) a generic quote-pairing regex (`/'([^'\n]+)'/g`) DESYNCS on an apostrophe inside prose or a comment — `the worker's own model` swallowed 15 real keys and produced 19 phantom "orphans"; anchor the match on the KEY SHAPE instead (`/(['\"])([a-z][a-z0-9_]*(?:\.[a-z0-9_]+)+)\1/g`) so a stray apostrophe cannot open a match. (2) The scan must SKIP `*.test.*` files, because tests deliberately reference keys that do not exist — that IS the assertion. Guard the scanner itself with a floor (`referenced.size > 300`), or a regex that silently matches nothing makes every other assertion in the file vacuously true.
- [2026-08-01][source:user][task:i18n][probation] The user's standing "validation never blocks" principle (a guard layer degrades with salvage+warn, only failing on unrecoverable corruption) does NOT extend to i18n: they asked explicitly for a missing key to "dispare erro ao rodar". Both hold at once because the failure is a BUILD defect, not user data — a half-translated screen has no salvageable reading, and the hole is fixed by adding one line, not by recovering state. The compromise shipped is strict-by-default with `HUU_I18N_STRICT=0` as the operator escape hatch. When a new guard is proposed, ask which of the two it is: degrade for anything that arrives from a run/user, fail loud for anything a developer can only get wrong at authoring time.
- [2026-08-01][source:inference][task:rebase-i18n][probation] The coverage test does NOT enforce completeness on a browser module — it only checks that every `data-i18n` attribute resolves and that Ink `.tsx` files import `t()`. A `web/client/modules/*.js` file full of hardcoded literals that simply never call `t()` (or worse, hardcoded pt-BR) sails through the whole i18n gate — typecheck, boot audit, coverage — because there is no missing KEY anywhere, just absent translation. This is exactly how a surface merged from a branch that forked BEFORE the i18n conversion (here `/pentest`: `pentest.js` + the `index.html` §pentest + the mode-switch tab) stays monolingual while all four nets stay green. Catching it is a manual sweep at merge time. When you do convert such a surface, mirror `web.dev.*` exactly: the catalog owns the WORDING, the server registry (`pentest-methodology.ts`) still owns the LIST, `render*()` looks up `t(\`web.pentest.playbook.${opt.key}.label\`)` keyed by option key, and the three runtime families (`web.pentest.phase.`/`playbook.`/`method.`) go in `coverage.test.ts` DYNAMIC_PREFIXES or the orphan check flags every member. Composite innerHTML strings with a `<strong>` (the session meta line) interpolate through `t()` with the dynamic values pre-`esc()`'d, since `interpolate()` does not escape.
- [2026-08-01][source:inference][task:dev-harness-rebase][probation] `src/lib/dev-mode/**` is NOT a translated surface and should stay that way — `dev-cli.ts` has zero `t()` calls, and its refusal messages (`huu dev: --<flag> expects …`) plus every `DevEvent.log` line are plain English. But `cli.help` IS translated and it CONTAINS a `dev flags:` block, so adding a dev flag means editing TWO catalogs even though the flag's own parser is untranslated. The seam is: the flag's DOCUMENTATION lives in i18n, the flag's IMPLEMENTATION does not. Nothing in the three enforcement layers catches a flag missing from the help block — `tsc`/boot/`t()` only see whole keys, and `cli.help` already exists in both locales — so this is a grep-the-help-text discipline, not a guarded one. Note `t('cli.help')` needs BOTH `envLines` and `configPath` params; calling it with one throws `MissingParamError` naming the other.
- [2026-08-01][source:inference][task:dev-harness-rebase][probation] `DevStopReason` values reach the browser as RAW CODES: `dev.js` renders `esc(session.stoppedBecause)` next to the translated label `web.dev.row_stopped`. So a NEW stop reason needs no catalog entry — same convention as `card-state.ts` returning English codes and translating only at the render boundary (`tStatus`). Adding `cost-ceiling`/`graceful-stop` correctly required zero i18n work; the tempting "add a label key per reason" would have been the drift, not the fix.
