- [2026-08-04][source:inference][task:onda7-launch-from-web][probation] The canvas must NOT start a dev session itself. A drawn run still needs a goal, a project directory and a model routing, and `/dev` already owns all three (`loadDevFolder`/`selectDevDir` write into FIXED ids inside `#viewDev`, so a modal on `/graph` would have to duplicate the folder browser). So `/graph`'s "Rodar este método" HANDS THE METHOD OVER: `runGraphInDevMode()` sets `S.devGraphId`/`S.devGraphName` and dispatches a `huu:run-graph` CustomEvent, `dev.js` listens and pre-selects it, and the ordinary /dev submit is the only thing that POSTs. It is a DOM event and not an import because `launch.js` already imports `graph/canvas.js` — importing back would close an ESM cycle.
- [2026-08-04][source:inference][task:onda7-launch-from-web][probation] "Is this drawing saved?" is answered by REFERENCE equality against the last document that came off the wire (`savedDoc === graph`), because every mutation in `graph-model.js` returns a new object. Set it on save, on open-from-library and on `/from-sample` (which writes before it answers); start it at `null`, since a canvas restored from `S.graphDoc` after a view swap can prove nothing about the file. It errs toward "unsaved", which is the harmless direction — `huu dev --graph` and `graphId` both read the FILE, so running an edited-but-unsaved canvas would run yesterday's method under today's drawing.
- [2026-08-04][source:inference][task:onda7-launch-from-web][probation] THE TWO `drawnMethod`s HAVE DIFFERENT KEYS AND BOTH ARE RIGHT. `DevSessionSnapshot.drawnMethod` is `{id, name, description?}` (what is RUNNING); `DevResumeOffer.drawnMethod` is `{graphId, graphName}` (verbatim from `DevState`, i.e. what is ON DISK). Reading one with the other's keys yields `undefined` and a resume that silently drops its method. Also: `POST /api/dev/resume` carries only `{accept}`, so a browser CANNOT add the drawing at accept time — `resolveDevGraph` reads the START params. The only correct recovery when the live attempt is not already carrying the offer's `graphId` is abort → poll `GET /api/dev` until `active === false` → re-POST `/api/dev` with `graphId` + `resume: 'auto'`. Nothing is lost: the refusal precedes every side effect.
- [2026-08-04][source:inference][task:onda7-launch-from-web][probation] On the graph path the /dev methodology flags and the per-role routing are still SENT and still recorded — the driver turns them into `graphSessionWarnings` → `planWarnings` and compiles neither. The honest UI is therefore to keep both panels on screen with a banner saying "not compiled into the drawing", never to hide them: hiding teaches that the choice does not exist and silently discards a selection the human wants back the moment they switch to the planner. `planWarnings` is where that is discovered, so it must render INDEPENDENTLY of `session.plan` being set (it used to hang off it and vanished in exactly the states that matter).
